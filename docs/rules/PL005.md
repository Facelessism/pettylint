# PL005 — disabled-test

**Category:** testing · **Default severity:** notice · **Default confidence:** medium
**Languages:** JavaScript, TypeScript · **Autofix:** not available

## Purpose

Detects explicitly skipped tests: `test.skip(...)`, `it.skip(...)`,
`describe.skip(...)`, `xit(...)`, and `xdescribe(...)`.

## Why it exists

A skipped test is a gap in coverage that's easy to forget about once it's
been skipped for a while. This rule surfaces skipped tests so they stay
visible, without claiming to understand *why* they were skipped.

## Examples that trigger

```ts
test.skip("does a thing", () => { ... });
it.skip("does another thing", () => { ... });
describe.skip("a whole suite", () => { ... });
xit("an old test", () => { ... });
xdescribe("an old suite", () => { ... });
```

## Examples that do not trigger

```ts
test("does a thing", () => { ... });

// Conditionally selected at the call site — not a literal `.skip` access,
// so PettyLint does not attempt to resolve it (that would require
// evaluating the expression):
(condition ? test.skip : test)("does a thing", () => { ... });
```

## Limitations

Detection is syntactic: it matches a literal `<object>.skip(...)` property
access on the identifiers `test`, `it`, or `describe`, or a literal call to
the identifiers `xit`/`xdescribe`. PettyLint does not attempt semantic
resolution of custom test frameworks or re-exported/aliased test helpers.
Confidence is `medium` rather than `high` because some codebases use
non-standard runners where these identifiers mean something else entirely.

## Suppression

```ts
// pettylint-disable-next-line disabled-test
it.skip("flaky on CI, tracked in TICKET-123", () => { ... });
```

## Autofix

Not provided. Un-skipping a test is a behavioral change PettyLint won't
make automatically.
