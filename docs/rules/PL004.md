# PL004 — todo

**Category:** documentation · **Default severity:** notice · **Default confidence:** high
**Languages:** JavaScript, TypeScript · **Autofix:** not available

## Purpose

Detects `TODO` and `FIXME` markers inside actual source comments.

## Why it exists

TODOs and FIXMEs are useful, but they're also easy to forget once they're
buried in a large file. Surfacing them keeps them visible without treating
them as errors — hence the `notice` default severity.

## Examples that trigger

```ts
// TODO: refactor this
// FIXME: broken authentication
/* TODO: remove later */
```

## Examples that do not trigger

```ts
const x = "TODO";     // inside a string literal
const y = "FIXME";    // inside a string literal

// things we still need to do eventually   (no TODO/FIXME marker present)
```

## Limitations

The marker must appear as a whole word immediately followed by a word
boundary or a colon (`TODO:`, `TODO ...`), matched case-sensitively against
the literal tokens `TODO` and `FIXME`. Lowercase `todo`/`fixme` and
alternative spellings are not detected; this keeps the rule's false-positive
rate low rather than trying to guess at every possible phrasing.

## Suppression

```ts
// pettylint-disable-next-line todo
// TODO: this one is tracked in an external ticket, not the source
```

## Autofix

Not provided. There is no safe mechanical fix for "someone should look at
this later" — the point of the finding is to surface it, not remove it.
