# PL001 — console-log

**Category:** debugging · **Default severity:** warning · **Default confidence:** high
**Languages:** JavaScript, TypeScript · **Autofix:** available for a narrow safe subset (`pettylint --fix`)

## Purpose

Detects `console.log`, `console.error`, `console.warn`, `console.info`,
`console.debug`, `console.table`, and `console.trace` calls.

## Why it exists

These calls are almost always added for local debugging and left behind by
accident. They clutter production logs and can leak information that
wasn't meant to be printed.

## Examples that trigger

```ts
console.log(request);
console.error("unexpected state", state);
```

## Examples that do not trigger

```ts
// console.log("debug")          // inside a comment

const text = "console.log()";    // inside a string literal

/*
console.log("also a comment")
*/

myLogger.log("this is a different object entirely");
```

## Limitations

Detection is syntactic (AST-based). Direct `console.<method>(...)` calls
are matched at `high` confidence. Three narrow `const`-alias forms are
additionally detected at `medium` confidence:

```ts
const c = console;          c.log(...)
const log = console.log;    log(...)
const { log } = console;    log(...)   // including renamed destructuring
```

Only `const` bindings are tracked, deliberately: a `const` cannot be
reassigned, which rules out the obvious false-positive case (an alias
identifier later repurposed for something unrelated) without requiring
real scope or type analysis. `let`/`var` aliases, reassignment, aliasing
through function parameters, and aliasing across files/imports are not
resolved — that would require executing or type-checking the code, which
PettyLint never does. This is a deliberate false-negative trade-off in
favor of a zero false-positive rate.

## Suppression

```ts
// pettylint-disable-next-line console-log
console.log("intentional, e.g. a CLI tool's own output");
```

## Autofix

`pettylint --fix` removes a `console.*` call only when removing it provably
cannot change anything except the log output. It declines (leaves the code
alone) unless **all** of these hold:

- the call is a direct `console.<method>(...)` (aliased, medium-confidence
  matches are never fixed);
- the call is a bare statement in a statement list, not part of an
  expression (`cond && console.log(x)`, `return console.log(x)`, an arrow
  function body, or `if (x) console.log(x)` are all skipped);
- every argument is an inert literal (string, number, `true`/`false`/`null`,
  or a template literal without substitutions). `console.log(user)` is not
  fixed because evaluating `user` could throw, and `console.log(getUser())`
  is not fixed because the call may have side effects;
- the file does not declare its own binding named `console`.

Anything else is reported but left for a human to decide.
